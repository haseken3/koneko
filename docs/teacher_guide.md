# 第1部：説明書

## 1. このツールは何か

ko-NeKo IDチェッカーは、オンデマンド授業教材（PowerPoint）を **鈴木克明 (2006) レイヤーモデル** に基づく **44項目のチェックリスト** で自動評価し、Word 形式のフィードバックを生成する Web ツールです。

- **入力**: PPTX ファイル（スライド本文 + ノート欄ナレーション原稿）
- **処理**: Anthropic Claude API による LLM 評価
- **出力**: Word ファイル（評価項目ごとのスコア・根拠・該当スライド）

「教員自身が制作した教材を客観視する補助」を主目的としています。教員の最終判断・修正の前段の素材としてご活用ください。

---

## 2. 使い方

### 2.1 アクセス
ブラウザで以下にアクセス：
```
https://koneko-idcheck.streamlit.app/
```

### 2.2 評価設定（サイドバー）
- **授業の年次**: 評価対象の授業を受講する学年を 1〜4年次から選択（詳細は 8 章「評価ペルソナ仕様」参照）

### 2.3 評価対象の PPTX をアップロード
- ドラッグ&ドロップ または「Browse files」から選択
- 上限 200MB
- アップロード後、スライド数・ノート付きスライド数・総文字数が表示されます

### 2.4 評価開始
- 「🚀 評価を開始」ボタンをクリック
- 進捗バー + 各項目のリアルタイム結果が表示されます
- **想定所要時間: 6〜9分**（42項目 × 約9〜12秒）

### 2.5 結果ダウンロード
- 評価完了後、「📥 Word フィードバックをダウンロード」ボタンが表示
- ファイル名は `{元のPPTX名}_IDフィードバック_{日時}.docx`

---

## 3. 評価結果の読み方

### 3.1 スコア
3水準で評価されます：

| スコア | 表示 | 意味 |
|---|---|---|
| +1 | 🟢 良好 | 評価項目に対して問題なし |
| 0 | ⚪ 中立 | 該当しない・判定保留 |
| -1 | 🔴 要改善 | 該当あり、改善余地あり |

### 3.2 Word ファイルの構成
1. **対象資料・評価日時** （ヘッダ情報）
2. **サマリ** （成功/失敗件数、スコア内訳）
3. **評価結果** （スコア別グルーピング）
   - 要改善が必要な項目（先頭）
   - 判定が中立の項目
   - 良好な項目
   - 評価に失敗した項目（末尾）
4. 各項目には **[項目ID] 評価観点 / スコア / 根拠 / 該当スライド** が記載

---

## 4. 注意事項

### 4.1 LLM 自動評価の性質
- **これは LLM による自動評価です**。教員の最終確認・修正の参考としてご活用ください
- LLM は確率的に動作するため、**同じ PPTX を再評価しても結果が完全には一致しないことがあります**
- 評価根拠（rationale）は具体的に書かれますが、教員から見て不適切な根拠の場合もあります

### 4.2 年次別ペルソナの偏り
- 年次選択は内部的に **学年代表の学生像1名（仮想ペルソナ）** に変換され、その視点で評価します
- このペルソナは「該当学年の代表的な学生像」を示すものであり、**その学年全体の総意を代表するものではありません**
- 「2年次」を選んだ場合の評価結果と「3年次」を選んだ場合の評価結果は、同じ教材でも異なります（評価視点が変わるため）

### 4.3 評価対象の範囲
- 現バージョンは **スライド本文 + ノート欄ナレーション原稿** のみを評価対象としています
- **画像・図・グラフは未対応**（テキストフレーム外の視覚要素は評価から除外）
- 図の中の説明が評価の鍵となる項目では「該当なし」判定になる可能性があります（v2 で対応予定）

### 4.4 入力サイズの上限
- 1教材あたりの推定トークン数が約 18 万を超える場合、エラーで停止します
- 該当する場合は、教材を複数 PPTX に分割してアップロードしてください

---

## 5. トラブルシューティング

| 症状 | 対処 |
|---|---|
| 評価が途中で止まる | ブラウザを更新し、再評価を実行 |
| 「⚠ 入力サイズ超過」 | 教材を分割（Step 単位など）して再アップロード |
| 「評価に失敗した項目」が複数 | API 一時不調の可能性、時間をおいて再実行 |
| ダウンロードボタンを押したら画面が消えた | ファイル自体はダウンロードされている、必要なら再評価で完了画面を再表示 |

## 7. 評価ロジック仕様

### 7.1 評価軸（鈴木克明 2006 レイヤーモデル）

| レベル | 名称 | 観点 |
|---|---|---|
| -1 | いらつきのなさ | 精神衛生上の要件（基本仕様・形式面） |
| 0 | ムダのなさ | SME 的要件（シラバス整合・対象者レベル） |
| 1 | わかりやすさ | 情報デザイン要件（レイアウト・ナレーション） |
| 2 | 学びやすさ | 学習効果要件（導入・まとめ・構成） |
| 3 | 学びたさ | 魅力要件（動機づけ） |

初年度（2026年度開講）は、レベル -1 / 0 / 1 を中心に評価します。

### 7.2 チェックリスト構造

`idcheck/checklist.json` に格納された 44 項目。各項目は以下の構造：

```json
{
  "id": "1.3",
  "level": 1,
  "title": "箇条書きで構造化されているか？",
  "note": "補足説明",
  "teacher_self_check": false,
  "llm_evaluable": true,
  "applicable_years": ["2026"]
}
```

- `teacher_self_check: true` の項目は教員自身で確認すべき項目（業務観点）として LLM 評価から除外
- 結果として LLM 評価対象は 44項目中 **42項目**

### 7.3 LLM 呼び出し設計

各評価項目について：

1. **System プロンプト**：
   - 評価軸（項目ID、レベル、観点、補足）
   - 評価ペルソナ（学年別の学生像）
   - 評価ルール（3水準・LLM 自動評価の制約）
2. **User プロンプト**：
   - 全スライドの本文 + ノート欄ナレーション原稿
3. **Tool 強制**：
   - `submit_evaluation` tool を `tool_choice` で強制
   - 出力スキーマ：`{ item_id, score (-1/0/1), rationale, related_slides[] }`
4. **prompt caching**：
   - System プロンプトに `cache_control: ephemeral` を付与（5分 TTL）

### 7.4 信頼性設計

#### 7.4.1 入力サイズ事前判定
- 評価ループ開始前に教材の総文字数を推定トークン数（×1.2）に換算
- 約 18 万トークン超は ValueError で即停止（44項目分の連鎖 BadRequestError = 課金事故を防止）

#### 7.4.2 リトライ・エラー分類
内側リトライ最大3回、例外を以下4種に分類：

| 種別 | 例 | 対応 |
|---|---|---|
| Retriable | `APIConnectionError` / `APITimeoutError` / `RateLimitError` / `InternalServerError` | 待機後リトライ |
| Non-retriable | `BadRequestError` / `AuthenticationError` / `NotFoundError` | 即時打ち切り |
| Unknown | 上記以外の例外 | 即時打ち切り |
| Silent-failure-avoided | リトライ枯渇 | マーカー付きで上位通知 |

#### 7.4.3 スコア正規化
LLM が tool schema に反して score を文字列で返した場合、`int` 化を試み、失敗時は 0（中立）にフォールバック。

## 8. 評価ペルソナ仕様

### 8.1 構成

学年別に4人の学生像プロファイルを `idcheck/personas/` に配置：

| ファイル | 学年 | 通称 | 性別 | 背骨1語 |
|---|---|---|---|---|
| `grade1_shin.md` | 1年 | シン | 男 | 不安の素朴さ |
| `grade2_mai.md` | 2年 | マイ | 女 | 素朴さ |
| `grade3_ken.md` | 3年 | ケン | 男 | 好奇心の素朴さ |
| `grade4_aya.md` | 4年 | レイ | 女 | 諦観の素朴さ |

UI の年次選択（1〜4年次）が内部で対応するペルソナファイルに変換されます。

### 8.2 ペルソナ設計の3原則

- **生語彙で書く**: 専門用語を使わず、学生本人が口にする言葉で記述
- **固有名人格化**: 「1年生B」のような層代理ではなく、固有のフルネーム・地域・家族・趣味を持つ1人として描写
- **二段翻訳**: 表層（学生の生語彙）と内部翻訳（制作者向け中間語）を併記

### 8.3 各ペルソナの内容

各ペルソナファイルには以下が含まれます：

- 背骨1語と継承する特性
- 基本情報（年齢・地域・家族構成）
- 「いま思ってること」（独白）
- 教材に求めること（jobs）
- 刺さるもの・離脱するもの
- 認知特性（抽象耐性・既習範囲・集中力・学習動機）
- 教員へのメッセージ
- 評価する時の二段翻訳テーブル

## 9. データフロー詳細

### 9.1 入力データ

PPTX から以下を抽出（python-pptx 経由）：

- スライド番号
- スライドタイトル（最初のテキストフレームの先頭1行）
- スライド本文（全テキストフレームの結合）
- ノート欄テキスト

**画像・図・グラフ等の視覚要素は抽出されません**（v0.1 制約）。

### 9.2 評価ループ

```
for item in checklist (42項目):
    for retry in [1, 2, 3]:
        response = Claude API call(
            system = build_system_prompt(persona, item),
            user = build_user_prompt(all_slides),
            tool = submit_evaluation,
            tool_choice = force
        )
        if response has tool_use:
            return evaluation
        else:
            retry
    return silent_failure_marker
```

### 9.3 出力データ構造

```python
{
    "item": { "id", "level", "title", ... },
    "result": {
        "ok": True/False,
        "evaluation": {
            "item_id": "1.3",
            "score": -1 | 0 | 1,
            "rationale": "...",
            "related_slides": [3, 5, 7]
        },
        "usage": { "input_tokens", "output_tokens", "cache_*" }
    }
}
```

### 9.4 Word 出力

スコア別グルーピング（要改善 → 中立 → 良好 → 失敗）で並べ、各項目に：
- スコアバッジ（色分け）
- 根拠（rationale）
- 該当スライド番号

## 10. v0.1 既知制約 / 今後の予定

### 10.1 v0.1 既知制約

- 画像・図・グラフ未対応（テキストのみ）
- 評価結果がブラウザ操作で消える場合あり（DL 自体は機能）
- LLM が稀にスコアを文字列で返した場合、中立(0)に正規化される（schema 違反フォールバック）
- 同じ PPTX を再評価しても結果が完全に一致しないことがある（LLM の確率的性質）
- prompt caching が現設計では効きにくい（cache_read = 0、現設計ではペルソナを system プロンプトに内包しているため項目ごとに system が変わり cache hit しない）→ v2 で構造修正予定

### 10.2 今後の予定（v2 候補）

- 画像・図の評価対応（Vision API 検討中）
- 評価結果の永続表示（操作で消えない）
- 年次選択を複数同時実行（1年次〜4年次 × 4視点で一括評価）
- 評価項目の絞り込み UI（特定レベルだけ評価）
- prompt caching 構造修正（ペルソナを system から分離）
- Opus / Sonnet 切替対応（コスト試算後）
